# Godot 精灵表规范与 AI 生成设计

适用 Godot 4.x(2026 年当前稳定版 4.5/4.6,旧版 3.x 工作流不兼容部分已注明)。

## 一、概念

精灵表(Sprite Sheet)又称纹理图集(Texture Atlas),将多个精灵帧打包进一张 PNG 均匀网格中。引擎只需上传一次纹理,按行列索引取帧。动画序列(walk/attack/idle)或静态资产集合(道具、UI)均可打包。GPU 只绑定一张纹理即可渲染大量精灵,draw call 与纹理切换显著降低。

## 二、引擎消费路径

Godot 不自动解析第三方 XML/JSON 图集元数据,除非安装对应插件或自写解析器。可靠路径是 PNG 优先。三种实现方式:

1. AnimatedSprite2D + SpriteFrames 资源
   最简单。创建 SpriteFrames 资源,用面板中 Add frames from Sprite Sheet 按横竖网格数切帧,定义动画帧序列、FPS、循环。适合角色动画与特效,内置 play()/stop()/loop。切帧参数为 Horizontal/Vertical 数量,编辑器实时显示蓝色网格预览,须逐一核对。

2. Sprite2D + AnimationPlayer
   更灵活。Sprite2D 开启 region_enabled 或直接设 hframes/vframes/frame 属性,由 AnimationPlayer 对 region_rect 或 frame 做关键帧。适合变时序、演出类动画。注意:AnimationTree 驱动 region 插值时需设 Callback Mode Discrete 为 Dominant,否则淡入淡出会插值矩形导致撕裂。

3. AtlasTexture 资源
   独立的 Texture2D 子资源,含 atlas(源纹理)、region(Rect2 区域)、margin 三个属性,可交给任何接受 Texture2D 的节点(Sprite2D、TextureRect、Button 图标、SpriteFrames 帧等),UV 映射由引擎处理。
   关键权衡:region_rect 存在节点场景文件内;AtlasTexture 是独立 .tres 文件。50 个敌人变体引用同一图集时,改图集布局后 .tres 重新生成即可全部生效,而 50 个场景内嵌 region_rect 需逐一手改。规范:跨场景复用的精灵一律用 AtlasTexture .tres,region_rect 仅用于一次性精灵。

4. TileSet 图集
   瓦片走 TileSet 编辑器的 atlas 页签,自动网格化,支持碰撞、导航、地形集(autotiling)。多个图集可合并为单个大图集。

选型速判:播放帧序列选 AnimatedSprite2D;单帧静态选 Sprite2D;数千相同实例(落叶、人群、粒子)选 MultiMeshInstance2D + AtlasTexture,一次 draw call 渲染上千实例,代价是牺牲逐实例脚本灵活性。

## 三、制表规范

### 网格与尺寸

- 均匀网格,所有帧尺寸严格一致,不做 trim(裁边)、不旋转打包——凡是要在 Godot 内切片的表一律如此,否则网格对不齐。
- 帧尺寸取 2 的幂:16x16 复古俯视角色,32x32 街机动作,48x48 稍大号人形,64x64 动作 RPG 主角,128x128 Boss 级。
- 帧间 padding 1 至 2 px,整表外沿 margin。像素艺术缩放播放时相邻帧会互相渗透(bleeding),2 px padding 或像素外扩(extrusion)可消除。
- 帧排列惯例:同一动画连续排一行,便于 SpriteFrames 按行区间添加,也利于脚本按 index 计算定位。
- 表总尺寸建议同为 2 的幂(如 512x512、1024x1024),利于 GPU 纹理处理与移动端压缩格式。

### 项目设置(像素艺术必做)

| 设置项       | 路径                                                            | 值                                 |
|--------------|-----------------------------------------------------------------|------------------------------------|
| 默认纹理过滤 | Rendering > Textures > Canvas Textures > Default Texture Filter | Nearest                            |
| 拉伸模式     | Display > Window > Stretch > Mode                               | viewport                           |
| 整数缩放     | Display > Window > Stretch > Scale Mode                         | integer                            |
| 2D 像素对齐  | Rendering > 2D > Snap 2D Transforms to Pixel                    | On                                 |
| 基础分辨率   | Display > Window > Size                                         | 配合瓦片尺寸,如 320x180 或 384x216 |

注意:纹理过滤在两处生效——项目默认值与每个 CanvasItem 节点的 texture_filter 覆盖,后者优先。像素艺术需两处均为 Nearest,只改项目设置而节点残留 Linear 仍会模糊。2D 变换像素对齐消除相机移动时的亚像素抖动,整数缩放保证任何窗口尺寸下像素大小均匀(代价是特定尺寸出现黑边)。

### 导入设置

PNG 带透明通道是唯一推荐格式,Godot 原生支持。选中文件在 Import 面板:Compress Mode 设 Lossless(像素艺术禁用 Lossy);Filter 保持 Project Default(前提是项目默认已设 Nearest);Repeat 设 Disabled(平铺纹理除外)。改完必须点 Reimport 才生效。

## 四、动画规范

- 动画命名与 GDScript 调用严格一致:play("run") 只匹配名为 run 的动画,区分大小写。
- FPS 与 speed_scale 必须大于 0,循环类动画(idle、walk)勾选 Loop。
- 帧时长参考:走跑循环每帧 60 至 120 ms,idle 呼吸类 100 至 200 ms。
- 切帧后逐一核对每个矩形,网格数填错会导致裁切、空白、重复或偏移帧,这是导入错误的首要来源。
- 动画状态机复杂时用 AnimationTree;简单切换直接代码调 play。

## 五、性能与分层

- 批处理条件:共享同一纹理与同一材质的 CanvasItem 才会被合批,因此尽量把相关精灵打进同一张图集。
- 分层绘制:CanvasLayer 管最外层(UI/世界/HUD 各一层);同层内 y_sort_enabled 处理俯视/等距遮挡(低 y 后画,即压在高 y 之上);z_index 手动强制层级,少用;树序兜底。
- 移动端纹理压缩走 Godot 标准导入管线:ASTC、ETC1/ETC2、DXT、Basis Universal(KTX2),按平台选择。

## 六、AI 生成精灵表

### 核心难点

扩散模型与像素艺术目标相反:模型倾向平滑渐变、抗锯齿、高细节,像素艺术要求硬边、限色调板、零抗锯齿、刻意低分辨率网格。通用模型把 pixel art 当风格滤镜近似,产出高分辨率插画再降采样,留下软渐变与杂色。生成必须显式施加硬约束。2026 年 Sprite Sheet Diffusion 一类研究用 ReferenceNet + 姿态引导 + 运动模块做时序一致性,产品端已能做出"帽子不会在帧间凭空增减"的水平,但仍需人工 QA。

### 一致性设计四锚点

跨帧、跨资产保持四项恒定:

1. 面部:骨相、瞳色、发型轮廓、识别标记。
2. 身体剪影:身高、体量、游戏缩放下的可读轮廓。
3. 调色板:固定 3 至 5 种服装主色,明文写出色值或色名,禁止近似色漂移。
4. 服装语法:披风长度、护甲块分布、武器形制。

### 提示词公式

结构:风格参照 + 主体 + 技术规格 + 动画细节。示例:

```
16-bit pixel art sprite of a space marine, full body, idle standing pose,
side-scroller perspective, for a video game. Limited 5-color palette
(dark grey, cyan, silver, black, red visor). Crisp clean pixel art,
sharp black outlines, no dithering, no anti-aliasing, 32x32 grid,
plain white background.
```

负向提示词:blurry, fuzzy, soft, gradient, anti-aliasing, dithering, interpolation, photorealistic, 3D, jpeg artifacts, noise, watermark。

要点:指定世代锚点(NES 4 色 32x32、SNES 16 色 64x64、现代 128x128)比笼统 retro 精确得多;调色板数量与分辨率写成硬规则;在工具原生尺寸生成,不要事后放大。

### 一致性技术栈

按可靠性排序,多手段叠加:

1. 参考图锁定:先生成一张定稿 idle 帧(基石资产),后续所有姿态 @-引用该图并逐字复用世代规格,只变动姿态词。GPT Image 2 对硬边与调色板约束最好,Nano Banana Pro 对角色相似度锁定最好。
2. 种子锁定:同一 seed 生成全部帧,锁定装甲配色、比例、风格。
3. IP-Adapter:以图像锚定身份、文本只控制姿态,强度 0.7 左右。
4. ControlNet OpenPose:目标姿态骨架约束生成,weight 0.8 至 1.0,denoiser 0.3 至 0.6(0.4 以下保真更高,四肢畸变时降)。Canny/Depth 可叠加保留像素明暗。
5. LoRA 微调:用自己的风格素材训练,等价于" house style ",Scenario.gg 走此路线;本地 Stable Diffusion + PixelArt LoRA 完全可控无用量上限,需本地 GPU。
6. 品牌包/风格卡:把定稿提示词、调色板、负面词固化成可复用模板(MyUP Brandkit、Sorceress identity card 思路),不再逐帧复制粘贴赌运气。

### 工作流

1. 定风格:锁定世代、调色板、分辨率,生成单张定稿 idle 帧。
2. 批量衍生:以定稿为参考图,枚举姿态(idle/walk/run/attack/jump/hit/victory),逐帧生成,每帧出 4 至 10 张挑优。
3. 清洗:去背景拿透明通道,量化到固定调色板(索引 PNG),Aseprite 手修边缘、消除杂色与帧间漂移(凭空出现/消失的帽饰、变色)。
4. 组表:统一帧尺寸 + 2 px padding,按动画分行排布,导出 PNG。
5. 入 Godot:按第二节规范导入切片,AnimatedSprite2D 试播。
6. 引擎内 QA:至少 5 个精灵放真实场景测,浏览器预览不等于场景内效果;核对帧对齐、缩放、时序、碰撞盒比例。

### 工具选型(2026)

- Leonardo.AI Game Assets:免费起步最强,内置透明背景开关,出动画帧序列。
- Scenario.gg:自训模型保跨资产一致性,最接近自家风格管线。
- Midjourney v7:原始画质最佳,但资产集一致性全靠提示词纪律;--ctune 有助于风格校准。
- 本地 Stable Diffusion + ControlNet + IP-Adapter + ComfyUI:完全可控,可脚本化批量出 50 帧以上,需 GPU。
- Sorceress、SEELE、SpriteFusion 等:直接产出 Godot 可用网格表的浏览器工具,速产原型。
- 共识结论:帧间一致性与精确调色板强制在所有工具中均未彻底解决,人工清洗与引擎内测试不可省。

## 七、陷阱清单

- 模糊:过滤不是 Nearest(两处都要改)或开了 mipmap。
- 渗色:帧间无 padding,缩放后相邻帧像素泄漏。
- 帧错位:横竖网格数与实际不符。
- 抖动:未开 Snap 2D Transforms to Pixel 或未用整数缩放。
- play 无反应:动画名不匹配、FPS 为 0、未勾 Loop。
- 只加纹理不动:帧必须加进 SpriteFrames 资源,光给节点贴纹理不会动。
- XML/JSON 不生效:无对应 importer/解析器,Godot 不自动转换。
- AI 素材直接上线:未清洗、未量化调色板、未引擎内测试。
- 批处理失效:精灵散落多张纹理导致 draw call 暴涨。
